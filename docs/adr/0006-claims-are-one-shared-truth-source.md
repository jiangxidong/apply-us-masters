# 主张是全局唯一的一等对象，文书与推荐信共用同一个集合

[#10](https://github.com/jiangxidong/EduApplication/issues/10) 把「主张」定成素材门槛的**单位**（硬约束 = 不许有无素材支撑的主张），
但把判据外显成**产物末尾的「主张 → 支撑素材」对照表**——即主张是**文书局部的、派生的**，没有独立的持久存在。

[#12](https://github.com/jiangxidong/EduApplication/issues/12) 的三条决议全部要求它**先于文书存在**：
推荐信的差异化轴是主张（不是素材）；support pack 门槛按主张判；
推荐人线的输入只有「候选人名单 + 主张清单」，因此可与文书线并行、**且应最早起**（推荐人要两三周）。

让推荐人线自建一套主张 = **第二个真相源**（竞品坑 #9：同一事实索引两遍，检索互相稀释），被
[#4](https://github.com/jiangxidong/EduApplication/issues/4) 的原则直接封死。

决定：**主张是全局一等对象，落盘在工作区根的 `claims.md`；全局只有一个主张集合，
文书与推荐信都从它取。** 模型上：**文书是申请人自述主张，推荐信是第三方佐证同一批主张**——
一份连贯的申请，两者论证的是同一个集合。

考虑过并否掉的两个更便宜的方案，都倒在同一条判别式上：

> **必须能表示「一条有零个支撑素材的主张」。**

- **主张作为素材的一个字段**（每条素材声明它支撑哪条主张）：主张只作为素材的属性存在，
  **零素材的主张在物理上无法表示**——而 #12 的三类缺口里第一类就是「缺素材 = 这条主张没有素材支撑」，
  #10 又承诺每个缺口带属性「属于哪条主张」。产品最需要暴露的缺口恰好不可表达。
- **读取时从素材现推**：同上，且推荐人线在文书动笔前就要跑，那时无从推起。

第二条支撑理由来自 #4 的派生视图判别式（「这行字为了保持为真，需不需要被改写？」）：
主张是**被撰写的判断**，不是从别处推得的镜像。这和 [#11](https://github.com/jiangxidong/EduApplication/issues/11) 的 `tier_basis`、
#12 的「主张 → 推荐人分配」是同一形状——那两处都已判定必须落盘。

## Consequences

**#10 的两处修订。**

1. 产物末尾的「主张 → 支撑素材」对照表从**判据表**降级为**渲染视图**：真相在 `claims.md`，
   对照表是现算的呈现。它仍是 [#14](https://github.com/jiangxidong/EduApplication/issues/14) 的回归检查项。
2. 文书从「**发明**主张」改为「**从主张清单里选**」。全局主张集因此 ⊇ 任何一篇文书用到的主张集。

**素材门槛的作用域随之收窄**：硬约束「不许有无素材支撑的主张」卡的是**进了成稿的主张**，
**不是全局集**——全局集里允许存在零素材的主张，那正是缺口本身。
一条 `materials` 为空的主张进不了任何成稿，但能进带缺口标注的骨架。

**两个消费方 ⇒ 落在根目录，不落 `essays/` 下。** 沿用 #12 把 `essays/materials/` 提到根 `materials/` 的同一条理由：
推荐信线是第二个消费方，`essays/` 前缀会说谎。

**「谁能证实」不进 `claims.md`。** [#13](https://github.com/jiangxidong/EduApplication/issues/13) 已定可验证性是**素材**的独立属性；
主张层再存一遍就是第二真相源，且会让 #12 的 pack 门槛在两处失配。
门槛本来就是纯派生：顺 `materials` 列跳到素材，读素材的可验证性。

**「唯一写入者」再破一次。** 主张必须先于文书存在（推荐人线最早起），却又要在文书阶段被打磨，
因此 `claims.md` 是**两阶段写**：冷启动/画像阶段落初稿，文书阶段打磨。
[#9](https://github.com/jiangxidong/EduApplication/issues/9) 的「owner = 唯一写入者、跨 owner 写一律禁止」在文件粒度上因此有了**第二个**反例
（第一个是 `channels/`，已由 [#23](https://github.com/jiangxidong/EduApplication/issues/23) 承接）。
两个反例合起来把 #23 的题面从「`channels/` 的例外」变成「唯一写入者必须按节/阶段定义，不能按文件」。

## 补充（[#30](https://github.com/jiangxidong/EduApplication/issues/30)）：通则是「边只存在持久化的消费端」，素材同理

本 ADR 的 Consequences 只把这条规则写成了主张层的一个实例（`claims.md` 不设 `used_in`）。#30 拿素材撞出了它的一般形态：

> **一条关系边，只存在它那个已经落盘的消费端；两端都存必漂移。**

#10 给素材定的 `已用于` 字段（记「哪几篇文书、哪些学校用过这条素材」）**删掉**，两个用途都不需要它：

- **防跨推荐人雷同**——在它被写下的同一节里就已被上一句驳回。[#12](https://github.com/jiangxidong/EduApplication/issues/12) §5 的原话是「轴 = **主张**……素材是主张的支撑物，**直接分素材是分错了层**」，紧接着却调了一个素材层字段来干这件事。边已经在持久化的消费端了：`recommenders.md` 的「主张 → 推荐人分配」（本 ADR 已认定它是真相源而非镜像）。
- **防跨校开头雷同**——**在架构上不成立**。#10 §8 自己定了跨校 **canonical + delta**，且把 delta 三类砍到只剩 `why this program`（字数裁剪归渲染物轴、AI 政策是 canonical 的全局属性）。开头段属于 canonical，**跨校本来就是同一份**：「前 3 校都拿 X 素材开头」是设计的必然结果，不是待警告的缺陷。真正值得防的是**同一所学校多篇文书之间**的开头雷同（Cornell 的 academic-sop 与 personal-statement、UIUC 的 q1 与 q2），那是篇与篇的事，与「哪些学校用过这条素材」无关。

**因此不新增任何派生视图。** 用途一溶解，用途二落在既有的分配上；「这条素材用过没有 / 有没有素材从没被用过」若要问，是扫全部消费端报余数，与待核实清单同形，现算现打。

**也不留可再生缓存。** [#4](https://github.com/jiangxidong/EduApplication/issues/4) 允许 `packets/` 持久化可推导内容，但那条豁免建立在「它是渲染终点、没人从它读回去」上；`已用于` 是**索引**，会被读回去做判断，漂移有后果，不满足前提。

**对 #10 的定性是「多余」，不是「错」。** 一字段两用途这个形态本身正当（`voice` 就是）；#10 的毛病是**把两个本来都不需要落盘的用途，当成了立字段的理由**。订正评论留在已关闭的 #10 上（同 [#23](https://github.com/jiangxidong/EduApplication/issues/23) 修 [#20](https://github.com/jiangxidong/EduApplication/issues/20) 的先例）。

**顺带补落一句本 ADR 一直依赖却没写下的前提**：判别式的完整形态需要「**「镜像」的前提是别处有源；没有源的可变内容是判断，不是镜像**」。#12 提出过它、状态层契约收了它，但 `main` 的 `CONTEXT.md` 只有单向的「不许存」半句——而 #30 的裁决恰是第一次真正用到它的场合。已补进 `CONTEXT.md` 的「派生视图」词条。

**两个消费端都已有实体**（[#27](https://github.com/jiangxidong/EduApplication/issues/27) 已完成并关闭）：`prototype/state-layer` 的样例里 `claims.md` 已建（四列，含一条 `materials` 为空的缺口主张），`essays/canonical/long.md` 的 frontmatter 已有 `claims: [c01, c02, c03]`。所以本裁决不是纸面通则——两端都存的那个物理机会**此刻就已经存在**，`已用于` 若加回去立刻就是漂移。

## 补充（[#32](https://github.com/jiangxidong/EduApplication/issues/32)）：判别式在散文上不自毁，靠的是「唯一正确取值」

上一节把 #30 的通则写成了「边只存在持久化的消费端」。#32 拿**渲染物**撞出了判别式本身的一个洞：
它对 `essays/canonical/` **逐字自毁**。

canonical 渲染物就是「把主张写成人话」的产物——`long.md` 的正文整篇都在复述 `claims.md` 的主张，
一条主张的措辞被打磨，正文「为了保持为真就得被改写」，而源确实在别处（`claims.md`）。
连 #12 补的前提句都拦不住：源是有的。**按字面读，整篇长文是镜像，该删。** 显然荒谬。

### 决定

**镜像 ⇔ 这段内容存在一个唯一正确的取值，而那个取值在工作区内的别处。**

散文没有唯一正确取值——措辞是手艺，两个 agent 各写一遍，差异是文风不是 bug。
表格单元格有：`points.md` 里 `论点` 那一格的正确取值，就是 `claims.md` 那一格的字符串，写别的就是错的。
**自测**：两个 agent 各写一遍，差异算 bug 还是算文风？**算 bug ⇒ 是镜像。**

⚠️ **被否掉的那条是「散文豁免」**（表格与字段受判别式管，散文不管）。它读起来更简单，但当场撞已锁决策：
状态层契约 §1.5 紧接着判别式的那句「任何文件都不写当前状态——不写素材几条、不写闸口几比几」**禁的正是散文**。
切口必须开在**有没有唯一正确取值**上，不能开在体裁上。

⚠️ **「工作区内」是限定的一部分**，不是修辞：`✓ <url>` 指向站外，站外页面不是工作区的真相源。
不写死这三个字，规则会误伤整个证据标记机制（[ADR 0007](0007-a-checkmark-is-earned-by-a-fetch-not-by-a-capability.md)）。

### Consequences

**`points.md` 的表整个删掉，不是删两列。** 票面问的是「`论点` / `素材` 两列该不该存」——两列确是镜像，
且**样例里已经实地漂开**：`claims.md` 的 c02 是「我的工程经验本身暴露了我**缺系统性的分布式系统训练**」，
表里写的是「我的工程经验暴露了**系统性训练的缺口**」，限定词丢了。镜像不是理论风险，是已发生的事。

但删到只剩 `claim_id` 一列仍不干净：**它与 frontmatter 的 `claims:` 互为镜像**。
而**分配能算出集合、集合算不出分配**，两处存必有一处是投影——按本节的判别式，
真要删一侧该删 frontmatter，可 frontmatter 才是本 ADR、[#21](https://github.com/jiangxidong/EduApplication/issues/21)、
`derive-demo.sh` 三处指定的边的落盘处，动不得。**唯一出口是让表消失**：
改四个 `###` 分节，节标题 = 题类（**自由文本，非封闭词表**），节内是那一段回答。
边只留在 frontmatter 一处，三个渲染物对机械读者一视同仁。

**空节 = 这类题还没有能写的东西，那就是缺口本身。** 沿用 #21 判「主张住哪」时用的同一把尺子——
**必须能表示空的那一侧**（#21 是「一条零素材的主张」，这里是「一道还没分配到主张的题」）。
🔴 顺带删掉样例里一处已锁决策的违反：原 P3 行写着「（待补 —— 素材不足 3 个）」，
`待补` 是当前状态、`素材不足 3 个` 还是 [#10](https://github.com/jiangxidong/EduApplication/issues/10)
早已降级为参考值的旧门槛，两处都撞「任何文件都不写当前状态」。

**`essays/canonical/*.md` 的正文因此不设结构契约**（状态层契约 §1.1 补落）。
三个渲染物统一为「frontmatter + 散文」一种形态，没有 `render_form` 需要破例。
**唯一一条正文规则是否定式**：正文里若出现引用其它真相源主键的表格，
该表只许存主键与本文件自己的判断，不得复述被引对象的内容。
被否掉的是「逐 `render_form` 定正文结构」——那等于让契约去管一篇文书该怎么写，
正是本节确认「没有唯一正确取值」的那一类。

**没有开新 ADR。** 本票判的是 #30 那条边的**另一个方向**（#30 判素材侧的 `已用于` 该不该存，
本票判渲染物侧对主张的复述该不该存），同一条通则的两个实例，落在同一条 ADR 上。
`docs/adr/` 此刻正有编号撞车待清（[#41](https://github.com/jiangxidong/EduApplication/issues/41)），新增编号风险也最高。
