# ADR 0018：全局参照表不进工作区，结论在渲染时现算

- 状态：已接受
- 日期：2026-08-15
- 来源：[#44 STEM/CIP 这条事实没有法定节收](https://github.com/jiangxidong/EduApplication/issues/44)、[#34 STEM 指定 / CIP code 在申请阶段可不可取证](https://github.com/jiangxidong/EduApplication/issues/34)

## 背景

「这个项目毕业后有没有 STEM OPT 资格」是留美倾向下选校的一条真实输入。[#34](https://github.com/jiangxidong/EduApplication/issues/34) 查实它**现在就可取证**：UIUC 大学层 Program Inventory 给 `11.0701 M.S. in Computer Science`，`11.0701` 在 DHS 2024 STEM 名单上，两环都是真取回。

但它不是一条事实，是**两条事实的函数**，而两条的形态完全不同：

| | 来源 | 属于谁 | 变化节奏 |
|---|---|---|---|
| `CIP code = 11.0701` | 该校 program inventory | **这个项目自己的属性** | 极慢，随项目改名/重编才变 |
| `11.0701 ∈ DHS STEM 清单` | DHS 一张全国名单 | **不属于任何学校、任何申请人** | 由第三方逐版更新（2022 → 2024） |

工作区里没有第二条的位置——`channels/<channel_key>.md` 逐渠道，`programs.md` 逐项目，而 DHS 清单与「这个申请人在申哪些项目」毫无关系。

## 决定

> **工作区只落 `CIP code`（带自己的 `✓ <inventory url>`）。「STEM 资格」是派生视图，渲染时现取 DHS 名单页算出来，从不落盘。**

取不回 DHS 页时，派生视图呈现「CIP 已核实为 `11.0701`，STEM 归属未核实」，并进既有的用户自查清单——这是地图已锁的那句「查不到，这是你要自己核实的清单」的又一次字面实现，零新机制。

判据是可复用的，不止管 STEM：

> **一条事实进不进工作区，判据是「它是不是这个申请人、或他在选的这个项目的属性」。全局参照表——与任何一所学校无关、由第三方逐版更新的那类——不是，落进来就是镜像。**

这条推理不是新的，是 [ADR 0007](0007-a-checkmark-is-earned-by-a-fetch-not-by-a-capability.md) 那条「探测结果**绝不落盘**：联网能力是运行时属性、不是申请人资产，落进工作区就是派生视图判别式里的**镜像**（换台机器就成假话）」换了个对象。CIP 不在此列：它与 deadline、学费同类，是**这个项目自己的**属性，本就该落盘。

## 否决的两条

**把 DHS 清单进薄硬编码层**（skill 包里带一份 CIP → STEM 对照表）。两条独立的理由：一是地图 Out of scope 已写死「硬编码的大型院校/项目数据库——写不完且必然腐烂」，DHS 清单只是小一号的同类；二是更硬的一条——**从包里读一张表不构成 ADR 0007 认的「取回」**（`✓` 的准入是「该 URL 的页面正文在本次会话中进过上下文」**或**用户提供），把它当证据等于造出第三条 `✓` 来源，而那条来源恰恰无法回答「事实取自哪一页」。

**把 STEM 结论作为独立事实落进覆盖层**，带自己的 `✓ <dhs url>`。三个项目就存三份同一条全局断言——**正是 [ADR 0008](0008-the-owner-binds-to-a-section-not-a-file.md) 瞄准的责任漂移**，且这次连「一个单元两个写入者」都不违反，检查抓不到。更硬的是**换季与换版不同步**：DHS 改版发生在任意时刻，而惰性降级只在换申请季时触发（ADR 0008 限定 4），两者之间必然留一段「DHS 已改版而工作区仍标 `✓`」的窗口。存一条会过期而没有过期机制的断言，比不存更糟。

## Consequences

**STEM 结论每次会话重算，永不持久化。** 这正是要买的东西：DHS 名单一改版，结论自动跟着变，不留任何陈旧 `✓`，也不需要为它设计第二套失效机制。代价是每次要呈现 STEM 时都得付一次取回，取回失败率不低（ADR 0007 已认下「全表 `待核实` 是常态而非异常」）。

**`CIP code` 的家是覆盖层，不是渠道层。** #34 已查实 CIP 与 `program_key` 两头对不上（Cornell 一个 graduate field 下 MEng/MS/PhD 共用一码；Columbia SIPA 一个 channel 内四个 MPA 变体四个 CIP），所以它住 `## 项目级差异` → `### <program_key>` → `#### 费用与资格`（归属见 ADR 0008 限定 5）。三个样例现在把 `待核实 STEM OPT 资格` 填在渠道层的 `## 费用与资格`，**两处都要改**：层级下沉，且内容从「STEM 资格」改成「CIP code」。

**派生视图清单多一项。** 「本项目是否 STEM」加入派生视图清单，与「待核实自查清单」同类（派生、不落盘）。清单本身住 `CONTEXT.md`，而它已知比契约短七项（[#42](https://github.com/jiangxidong/EduApplication/issues/42)）——本条一并交给 #42，不在此处补。

**不新增检查。** 「STEM 结论没有被落盘」这件事，机械上表现为「工作区里不出现某个自由文本」，而 `待核实` 行是自由文本、没有封闭词表（`CONTRACT.md` §1.2 已为「同一条事实」拒绝过同一种检查）。它靠契约措辞约束，不靠脚本——同 ADR 0008 限定 2 `claims.md` 那条的纪律。

**反向不可逆。** 一旦把 DHS 判断结果冻进某个 `✓`，收回它要重扫全部工作区里的 STEM 行并逐条降级，而降级后无法区分「本来就没查」与「查过但清单已改版」。

## 落地在别处

契约侧（`CONTRACT.md` §1.2 的范围话与覆盖层示例）与样例侧（三个 channel 文件）的改动**不在本条**——它们只活在 prototype 分支，转 [#58](https://github.com/jiangxidong/EduApplication/issues/58)。⚠️ 样例改动**只做层级下沉与内容改形，保持 `待核实`**，不得就地打 `✓`：「样例里一条 `✓` 事实都没有」这条边界归 [#31](https://github.com/jiangxidong/EduApplication/issues/31)。
