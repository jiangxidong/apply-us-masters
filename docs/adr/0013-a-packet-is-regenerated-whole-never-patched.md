# ADR 0013：准备包整包重生成，绝不就地改

- 状态：已接受
- 日期：2026-08-15
- 来源：[#8 网申准备包的交付形态](https://github.com/jiangxidong/EduApplication/issues/8)
- 原编号：**0011**。落盘时（[`d262e75`](https://github.com/jiangxidong/EduApplication/commit/d262e75)）与并行 session 的 [ADR 0011 词汇表定义词，契约持有取值](0011-the-glossary-defines-words-the-contract-holds-the-values.md)（[`fbc2d00`](https://github.com/jiangxidong/EduApplication/commit/fbc2d00)，[#26](https://github.com/jiangxidong/EduApplication/issues/26)）撞号，按提交顺序本条后落、让号，由 [`a15d5ec`](https://github.com/jiangxidong/EduApplication/commit/a15d5ec) 改为 0013（0012 已被 [#15](https://github.com/jiangxidong/EduApplication/issues/15) 占用）。#8 评论里**改号之前**写下的「ADR 0011」指本条——两条死链（原型交付评论、决议第 2 节）与两处裸引用（推论 2、决议末段）；**唯一的例外是记录改号那条评论本身**，它写的「ADR 0011」反指词汇表那条。那些是不可变历史，改不动。

## 背景

`packets/<program_key>/` 是**落盘的可再生层**（状态层契约 §1.1）。这两个性质放在一起就有洞：
落盘意味着它会被人读、被人带走、被人手改；可再生意味着它随时可能与真相源不一致。

洞是具体的：canonical 文书出到 v2、`channels/` 换季把一条约束降级成待核实，
包里对应的渲染物和转述**当场变成假的**，而它看上去和真的一模一样。
「上一季打了勾的条目比没打勾的更危险」这条竞品坑（见 [ADR 0002](0002-one-program-pool-one-status-axis.md) 的背景）
在这一层会以最坏的形式复发——因为包是用户**照着抄进 portal** 的那一份。

三条路：整包重生成 / 落盘加陈旧警告但不自动重生成 / 干脆不落盘每次现打。

## 决定

**整包重生成，绝不就地改。**

包的 frontmatter 记 `source_fingerprint`：生成那一刻每个真相源的 `cksum`。
进入准备包阶段先比对——**不一致就整包删了重生成，一致就直接用**。

推论三条：

1. **在包里直接改内容，下次重生成时静默丢失。** 要改内容改真相源。
   这条必须写进包的开头，否则用户会以为包是可编辑的草稿。
2. **包内允许镜像。** 交还点总表、缺口表、渲染物都是别处内容的重述——它们合法，
   **唯一前提就是本 ADR**。这也是「派生视图完全不落盘」与「`packets/` 落盘」不矛盾的地方：
   前者管的是真相源旁边的常驻文件，后者是一个每次整体重算的层。
3. `source_fingerprint` **不是镜像**：它记的是「生成那一刻源是什么样」，
   是历史观察值，同 `log.md` 的镜像豁免；它从不被改写，只随整包一起重生成。

## 为什么不选另外两条

**落盘 + 陈旧警告、由用户决定重不重生成**：把不可逆的判断交给了最没有信息的一方。
用户看到「long.md 已到 v2，要重新生成吗」答不上来——他不知道 v2 改了哪里、影响哪一段。
而答错的后果是拿着一份旧文书去提交，且这一步在多数学校不可逆。

**不落盘、每次现打进对话**：与「跨会话状态层是核心赌注」直接冲突——
产品的**最终交付物**反而是唯一不落盘的东西。用户换一台电脑、想打印、想隔天再走一遍，手里什么都没有。

## 代价

- **每次进入准备包阶段都要重跑一遍渲染**，即使一个字没改（比对是便宜的，重生成不是）。
- **用户手改包会静默丢失**。这是真代价，只能靠包开头那句话和形态本身（它读起来像一份清单，不像草稿）来降低。
- 指纹用 `cksum` 不用 `mtime`：**实测 `git checkout` 会把全部文件的 mtime 刷成同一个值**，
  新克隆的仓库里 mtime 恒定失配，等于「每次都重生成」，检测不出任何东西。

## 作废条件

- 若将来允许用户在包里就地编辑（例如包变成可交互的填表器），推论 2 当场作废——
  交还点总表与缺口表会退化成镜像，必须改回派生视图。
- 若真相源多到 `cksum` 全表比对变慢（数十个渠道 × 数十个项目），比对粒度需重算。
