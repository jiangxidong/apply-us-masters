# ADR 0023：一个词两义时，判别式判不过自己名字的那一义让名

- 状态：已接受
- 日期：2026-08-16
- 来源：[#73 「渲染物」一词两义：词汇表是窄义，契约 §2/§1.5 是宽义](https://github.com/jiangxidong/EduApplication/issues/73)

## 背景

[#60](https://github.com/jiangxidong/EduApplication/issues/60) 给 `support pack` 立词条时**拒绝**写「它是渲染物」，理由是这个词在两处是两个意思，写了就要在窄义词条下制造一个反例。那次回避是对的，但它把账留给了本票。

### 一、票面的前提要更正一处：**§1.5 不是宽义现场**

票面说宽义住在「契约 §2 / §1.5」。**§1.5 只出现过一次「渲染物」**（`CONTRACT.md:476`，「canonical 渲染物本来就是『把主张写成人话』的产物」）——那是**窄义**。真正的宽义现场是 §1.1、§1.3、§2，而且票面不知道的那一半更重：

```console
$ git grep -n '渲染物' main prototype/state-layer prototype/application-packet
```

| 义 | 现场 |
|---|---|
| **窄**（canonical 文书的三个写法） | `CONTEXT.md` 词条本身 + 版本词条 + 派生视图词条 + 落盘键表 4 行；`CONTRACT.md` §1.1 `:65/:177/:182/:192/:207/:230`、§1.5 `:476`、§5 `:817/:818`、§6 `:836`；`README.md:33`、`derive-demo.sh:76`、`apply.md:29`、`essays/canonical/README.md:8`、`log.md:15` |
| **宽**（内容层经渲染产出的东西） | `CONTRACT.md` §1.1 `:218`、§1.3 `:383`、§2 `:512/:513`；`documents/README.md:15`；**`packets/README.md:109`、`trace-packet.sh` 检查 [3]、五个 packet 文书成品的正文抬头** |

⚠️ 最后那一栏是票面完全没有的：**宽义已经长进了产物与脚本**——`trace-packet.sh` 的检查 [3] 就叫「每个渲染物的 `rendered_from:` 真相源存在」，而 `rendered_from` 是一个**已落盘的 frontmatter 键**。宽义不是散文里的随口用法，它有实现体。

### 二、两义不是宽窄，是**同一条边的两端**

按「宽义 ⊃ 窄义」去读，会得出「把词条放宽就完了」的结论。**实测不成立：两义的外延不相交，且互为否定。**

`packets/cornell--gradschool--cs-meng/essays/academic-sop.md`（宽义渲染物）的 frontmatter 里写着 `rendered_from: essays/canonical/long.md`，而 `long.md` 正是三个窄义渲染物之一。**一个词同时挂在同一条 `rendered_from:` 边的两端。**

更硬的一刀：`CONTEXT.md` 的「canonical」词条把 canonical 定义成**「既非派生视图、也非可再生产物」**。三个窄义渲染物**全部住在 canonical 层**（§2 那张图的左边、§1.1 第 7 行的 owner 是文书）。所以按本仓库自己的定义，**窄义的那三个东西恰恰不是渲染出来的东西**。

## 决定

> **一个词有两义时，先把两义各自的所指送进这个词自己的判别式。判不过的那一义让名。**
> **让名之后的新名字必须是仓库正文里已经在用的词，不许现造。**

第二句是第一句的止损条件：没有它，「让名」会退化成造词，而造词是 [ADR 0022](0022-a-name-outside-the-vocabulary-is-not-a-reason-to-add-one.md) 判死的形态。

落到本票：

| 义 | 送进「渲染物」的判别式（这东西是渲染出来的吗） | 判 |
|---|---|---|
| 宽 | 是。`rendered_from:` 是已落盘的键，`trace-packet.sh` 在查它 | **留名** |
| 窄 | **否**。它们是 canonical，按「canonical」词条是「既非派生视图、也非可再生产物」 | **让名** |

**窄义的新名字是「形态」，不是新词**——`CONTEXT.md` 里已经写着「它既不开**形态轴**也不开版本轴」、「`render_form` ……它是**形态轴**的名字」，`CONTRACT.md` §5 那三个写法也自陈「是**三种形态**」。词表这一侧**从来就管这根轴叫形态轴**，只是词条的头顶着另一个名字；契约那边同一根轴叫「渲染物轴」，一并跟上。

**对称性佐证**：`CONTEXT.md` 的「文书」节里，「版本」词条正是**版本轴**上的取值，且「版本」同样是个日常词。「形态 / 版本」成对，恰好就是 §5 那两根正交轴。

## 被否掉的三条

**① 给窄义加限定词造新词（「文书渲染物」「canonical 渲染物」）。** 它保住了「渲染物」三个字在两处都出现，读者仍要在每一次遭遇时判一次这是哪一义——**歧义没消，只是加了脚注**。而且它现造词，撞 ADR 0022。

**② 反过来：宽义让名，契约改说「可再生产物」。** 三处硬伤：
- **「可再生产物」在 `main` 上没有词条**，只在「canonical」词条的判别式里当否定项出现过一次。改用它 = 制造一个**用而未定义**的词——正是 #60 在 `support pack` 身上诊断出、并因此立词条的那个缺陷。
- 它**判不了 support pack**：support pack 不落盘，说它是「产物」要先解释一遍「不落盘的东西也算产物」，而「渲染物」一个字都不用解释。
- 它要动的是**已落盘的产物与脚本**（五个 packet 文书抬头 + `trace-packet.sh` + `packets/README.md`），而 packet 受 [ADR 0013](0013-a-packet-is-regenerated-whole-never-patched.md) 管，**改抬头就得整包重生成**。让名让给成本更高的那一侧，只为迁就一个没有词条的词。

**③ 两义都留，加一条消歧注。** 这是 [ADR 0011](0011-the-glossary-defines-words-the-contract-holds-the-values.md) 已经判死的形态的同构版——它当年否掉「允许重复，但脚本校验两处一致」的理由是「**它把漂移从不可见变成可检出，却承认了漂移的存在**」。消歧注同理：承认一个词指着一条边的两端，然后请每个读者每次自己判方向。

## Consequences

**宽义现场一个字都不用改。** 这是本决定最便宜的一面，也值得写下来免得下一个人白拆一遍包：五个 packet 文书标题后缀的「（渲染物）」、Cornell 那篇另有的「🔴 **这是渲染物，不是真相源。** 要改内容改 `essays/canonical/long.md`」、`trace-packet.sh` 的检查 [3]、`packets/README.md:109`、`documents/README.md:15`、`CONTRACT.md` 的 `:218/:383/:512/:513` —— **全部按新定义逐字成立**，包正文一个字节未动。

⚠️ **但 ADR 0013 仍然被触发了一次，而且是从没人预料的那一侧。** 落盘时把 `sample-workspace/apply.md` 目录导引表里的「文书 canonical 渲染物」改成「文书 canonical（三个形态）」——那是一行**没有任何包引用**的说明文字，`trace-packet.sh` 检查 [4] 当场报 🔴，因为 `apply.md` **整份进 `source_fingerprint`**（`packets/README.md:52` 明写：不进指纹的话换季不会让任何包失效）。⇒ **指纹的粒度是文件，改一个错别字与改一条约束在它眼里没有区别。** 按 [#65](https://github.com/jiangxidong/EduApplication/issues/65) 的先例重算指纹（两个包各一行，包正文零字节改动），复跑 0 🔴。**先例：一次纯措辞的重命名也会摊到已落盘的产物上，别把「不改内容」当成「不碰包」。**

**#60 的那次回避，结论保留、理由作废。** 「support pack 是渲染物」现在是**真话、也可以说**——但新词条**仍然不写它**，换了个理由：按 [#42](https://github.com/jiangxidong/EduApplication/issues/42) ②，词条该写的是 X 的**内涵**（「它是派生视图」），而「它在渲染箭头的哪一边」是**层的事实**，住 `CONTRACT.md` §2。`support pack` 词条**一个字不改**。#60 转出的这一项到此结清。

**词条头改名是本仓库第一次。** 此前的落位调整都是搬家（#26 / #42），没有动过词条的名字。为此在两个词条里各留一条互指：「形态」词条写明它曾叫「渲染物」，新「渲染物」词条写明它不指那三个写法。**旧票与旧评论里的「渲染物」永远改不动**，照字面读会**静默**落到另一义上——同 ADR 0011 那条改号提示、同地图 Notes「改号时两头都要留痕」。

**不新增机械检查。** 想得到的形态是「`essays/canonical/` 语境里不得出现『渲染物』」，它要判的是**语境**不是字符串，纯 `grep` 判不了，白名单一开就退化成花名册。按 [ADR 0019](0019-an-absence-needs-a-consumer-branch-not-a-registry.md) 甲类：**不开票、不进 `docs/checks.md`**。往一份至今没有实现体的清单里再加一行散文，正是 ADR 0011 Consequences 末段点名的那个形态。

**判据可复用，但今天只有一个样本。** 「判不过自己名字的那一义让名」写成通则，而它只在「渲染物」这一个词上跑过一次——**没有第二个样本，别把它当已复验的机器**。⚠️ 它也**不是** ADR 0022 的替代：0022 管「没有这个词，要不要加」，本条管「有这个词，两义谁留名」，两条的入口不同。

**反向代价：低。** 改名可逆——把「形态」改回去是一次全仓 `git grep` 加十几处编辑。真正难回头的是判据，不是名字。
