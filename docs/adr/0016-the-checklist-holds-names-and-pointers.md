# 检查清单只持名与指针，不复述规则

[ADR 0008](0008-the-owner-binds-to-a-section-not-a-file.md) 写着「孤儿检查脚本因此扩到六条」，`CONTRACT.md` §1.4 写着「孤儿检查脚本的第 1 条就是……」。两处都在用定冠词说话，像在指一个存在的东西。**它不存在**——`prototype/state-layer` 上唯一的 `.sh` 是 `derive-demo.sh`，里面没有任何节 / owner 检查。那几条**全是散文**，从来没有被执行过一次。

这不是「欠了一个脚本」。查证发现的是**同一份清单已经有第二份，而且已经分叉**。

## 病灶：清单是镜像，而镜像会漂

[#14](https://github.com/jiangxidong/EduApplication/issues/14) 的回归清单把其中三条抄进了自己的 G / E 组，并且是明知故犯——它的原话是「这三条走 #9 的孤儿检查脚本（不进 CI），本票只需决定要不要在 dry-run 回归里也断言一遍」，然后它答了「要」。

**两份已经不一致，实测：**

```sh
# G1 原文（#14 于 15:35 关票，无剥离步骤）跑当前 sample-workspace：
  ✗ FAIL(0) columbia--seas.md   :: 🔴 硬约束
  ✗ FAIL(0) columbia--seas.md   :: 🔴 推荐信机制 —— 风险 A：冒名发信
  ✗ FAIL(0) cornell--gradschool.md :: 🔴 冻结点 —— 全样本最硬的一个
  ✗ FAIL(0) cornell--gradschool.md :: 🔴 推荐信机制 —— 风险 A + 两个反直觉例外
  ✗ FAIL(0) uiuc--gradcollege.md   :: 🔴 冻结点 —— 与 Cornell 语义相反
  ✗ FAIL(0) uiuc--gradcollege.md   :: 🔴 推荐信机制 —— 风险 B：冒名复用
# ADR 0008 第 2 条（[#28](https://github.com/jiangxidong/EduApplication/issues/28) 于 17:04 加了剥离）跑同一批文件：0 FAIL
```

**G1 报 6 个假失败**，因为它比 #28 早关票 89 分钟，没人回去改它。反方向也有：#14 的 G2 比 ADR 0008 第 6 条**多一个合取项**。同一条规则的两份表述，两个方向各漂一次。

按 [ADR 0011](0011-the-glossary-defines-words-the-contract-holds-the-values.md) 的镜像判别式——「这行字为了保持为真，需不需要在别处改动时被改写？」——**一份复述规则文本的检查清单就是镜像**。G1 恰恰是因为别处（#28）改了而失真的，它是这条判别式的又一个实例。

序号是同一个病的第二副面孔。ADR 0011 的两条机械形态本该成为「第 7、8 条」，而**第 7 条已被 [#25](https://github.com/jiangxidong/EduApplication/issues/25) 用掉、第 8 条已被 [#37](https://github.com/jiangxidong/EduApplication/issues/37) 用掉**——两次撞号都发生在本票开着的时候，不是推理出来的风险。序号排的是「谁先被想到」，没人维护得了它；这与 [#24](https://github.com/jiangxidong/EduApplication/issues/24) 干掉的那个「第 12 个文件」是同一个失效方式。

## 决定

**三条，一起才闭环。**

> **① 清单只持名与指针。** 规则文本的唯一权威留在**裁决它的那份 ADR 或契约条款**里；清单持有的是「有哪些检查、它叫什么、被测对象是什么、规则原文在哪、跑在哪个夹具上」。反过来，ADR 与契约里所有「孤儿检查第 N 条是……」的复述**全部改成指针**。

> **② 分类的键是「被测对象」，不是「读了哪些文件」。** 每条检查都可以把契约当参考数据去查；把它们分开的是**它能宣布谁违规**。取值三种：`契约`（契约自己内部不自洽）／`repo 文档`／`工作区`。

> **③ 废除序号，改稳定短名。** 命名判据：**只给会被表外引用的检查起名**。

落成 [`docs/checks.md`](../checks.md)，十三条。这是 ADR 0011 对十节归属表下过的那一刀抬一层用在检查上：**词汇表定义词、契约持有取值** → **ADR 裁决规则、清单持有名与归属**。

## 被否掉的

**合并进 #14 的回归清单。** 那张表按 persona 组织、按工作区状态断言，而 `契约` 与 `repo 文档` 两类检查的被测对象根本不是工作区——`no-second-path-literal`（#14 F4）今天就挂在 F 组标着「两模式 / 全部 persona」，跑三遍 persona 得到三次相同结果，纯浪费，且掩盖了它从没被真正断言过。本决定把它与 `skills-never-cite-evals`（#14 G5）一并归位。

**切成两个文件。** 两个文件会各自长出自己的表头与约定，那本身就是下一次漂移的形态；而 ADR 0011 已经说过「拆开会造出一个没有任何消费者的产物」。切线是真的，但它是**一列的取值**，不是文件边界——#14 自己就把 D/E/F/G/X/T 六组放在一处。

**允许两份并存，加一条一致性元检查。** ADR 0011 已经否过这个形态：它把漂移从不可见变成可检出，却**承认了漂移的存在**，而判据说的是这行字根本不该有第二份。

**打包进 skill、在用户机器上跑。** 三条理由，两条是实测：① **检查自己会写错，已经六次**（详见 `docs/checks.md`），在用户机器上一个写错的检查告诉用户「你的工作区坏了」比不检查更坏；② 它**绑 locale 且静默失效**，而用户那台机器的 `awk` 版本与 locale 不受我们控制；③ 更根本的——运行时真正的保护是**写入前的规则**（契约措辞约束 agent 该写什么节名），不是**写入后的审计**：agent 刚写错了节名，再跑一个脚本告诉它写错了，它凭什么第二次就写对。这与 [#25](https://github.com/jiangxidong/EduApplication/issues/25) 拒绝把 `claims.md` 的 append/rewrite 分工做成检查是同一条理由——**有些规则是写给 skill 的行为规则，靠措辞约束，不靠脚本**。

**给 #14 全表改名。** 序号坏在跨文档引用；只在表内出现、没人从外面引用的条目留着序号一分钱不花。全表改名是买不到东西的大工程。

## Consequences

**「孤儿检查脚本」作为一个单一产物不再存在。** 它被拆成两个 runner：`契约` 与 `repo 文档` 走 `evals/checks/check-docs.sh`，`工作区` 走回归套件的静态检查组。ADR 0008 与 ADR 0011 里那个定冠词指向的东西，从此指向 `docs/checks.md` 而不是某个脚本。

**`evals/` 的含义扩大为「不流向用户的一切」，不只是测试数据。** 检查脚本与违规夹具都住进 `evals/`，**白拿 [ADR 0010](0010-personas-ignite-assertions-they-are-not-examples.md) 那条「任何 `SKILL.md` 不得引用 `evals/`」的红线**——不必为「检查脚本不该被打包进 skill」另立第二条规矩。放在 `scripts/` 或 `tools/` 则是红线管不到的新目录，还得再写一条去挡它。

**触发仍是手动，失效模式明写。** 不进 CI（#9 定的是「暂不进 CI」，而「哪些进 CI」归地图 fog）。配一条纪律：改动 ADR 0008 / 0010 / 0011 / 0016 或 `CONTRACT.md` §0 / §1 / §4 的提交，**结案评论必须附跑过的命令与输出**。**纪律不是执法**——G1 分叉 89 分钟无人发现，正是靠「有人会记得跑」。这是本决定明知而接受的软肋。

**`main` 上出现第一个 `.sh`，且它要跨分支读契约。** `CONTEXT.md` 在 `main`、`CONTRACT.md` 在未合并的 `prototype/state-layer`，脚本落 `main` 并用 `git show prototype/state-layer:…` 读契约那半。落 `main` 而不落 prototype 分支的理由是重心：契约迟早合进 `main`，`CONTEXT.md` 不会搬去 prototype 分支；合并那天只需删掉一个 `git show` 前缀。

**工作区那批跑两个夹具。** `sample-workspace/`（人手搭，防手误）与三个 persona 工作区（构建脚本展开，防展开逻辑写错）是**两种不同的错误来源**，都要跑。

**🔴 顺带推翻了 `CONTRACT.md` §4.5 的一句话。** 落盘取证时实测（`awk version 20200816`，`LC_ALL=en_US.UTF-8`）：`"硬约束" == "冻结点"` 返回 **1**。成因与 §4.5 已记的 `uniq` / `sort -u` **是同一个**——该 locale 下汉字没有排序权重，`strcoll` 对任意两个纯中文串返回 0，于是整个「比较相等」族失灵。§4.5 把病灶记成「两个 BSD 工具坏了」并写下「`sort`、`grep`、`awk` 都正常」，**`awk` 那半是错的**。而且**没有任何一个 locale 能同时救两件事**：`LC_ALL=C` 修好 `==` 却让剥离步骤失效。规则因此是「保持 UTF-8 locale，禁止用 `==` / `!=` / `<` 比中文，相等判断走 `index` 或正则」。契约侧的更正转 [#53](https://github.com/jiangxidong/EduApplication/issues/53)。

**反向不可逆的代价是中等。** 「清单只持名与指针」一旦成为机器，改判据要重扫所有引用检查的文档；短名一旦被 ADR 与契约引用，改名要同步改所有引用处。位置本身可逆，判据不可逆——同 ADR 0011 的自评。

**它不保证检查真的被跑。** 本决定只把「检查以什么形态存在、归谁」定死，**一行实现代码都没写**。若 `evals/` 始终不建，这份清单就退化成第三份从未被执行过的散文——它要治的正是这个病。唯一顶着它的是上面那条取证纪律，以及验收标准里的 dry-run 回归。
