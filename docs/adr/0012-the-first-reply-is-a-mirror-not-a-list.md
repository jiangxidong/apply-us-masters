# 首轮草案是一面镜子，不是一份清单

竞品在冷启动这一屏上给出的最好机制叫 **First-Reply Contract**：先给一份可用草案，标出其中的假设，**只问一个问题**，并提供一个本地表单出口（`euro-grad-apply` `SKILL.md:32-36`、`taught-master` `SKILL.md:95-100`，见 `docs/research/competitor-skills.md:30`）。它治的是 5/5 竞品全中的那个病——无状态 + 长周期 = 每次会话重新 intake（同文件 `:39`）。它值得抄。

但「先给可用草案」在本产品有一个别处没有的前提：**草案里写什么，是被取证纪律管着的。**

冷启动这一刻，`channels/` 是空的，本会话的取回次数是 **0**。此时 agent 能写出的任何学校事实——deadline、最低 GPA、文书字数、要几封推荐信——**只能来自记忆**。而记忆产出的学校事实正是停手线取证类唯一那一条禁止的东西（[ADR 0007](0007-a-checkmark-is-earned-by-a-fetch-not-by-a-capability.md)）。

于是「首屏就给一份选校草案」——竞品做得最抓人、留存率最高的那个形态——在本产品是**不合法**的。

有一个看起来能绕过去的写法，值得单独杀掉：**给项目列表，但整列标 `待核实`**。它没有打 `✓`，字面上不违反任何一条。真正的问题在于，`programs.md` 里凭记忆铺出的**一行本身就是一个断言**——「这个项目存在、且值得你看」。#16 已经定了「想分档必须先把事实收进 `channels/`」，铺 15 行 `待核实` 是**把取证劳动伪装成进度**：用户看到满屏的行，会以为已经开始了，而实际上一条都没查。

决定：**首轮草案的内容只能落在申请人自己这一侧。**

首屏交付的是**「我从你带来的材料里读到的你」**——`profile.md` 的骨架与 `claims.md` 的初稿——而**不是**「你该申哪些学校」。这一侧的取证成本是零：它的真相源就是用户本人，没有第二个权威需要去核。状态层契约把这两个文件的 owner 恰好给了冷启动/画像阶段，首轮契约与唯一写入者天然对齐，不需要任何跨 owner 的写。

两条推论，各堵一个漏：

**假设标注不设持久标记。** 抽出来的条目**整块摆出**（不是逐条追问，遵 [#10](https://github.com/jiangxidong/EduApplication/issues/10) 已定的「一次批量 3-5 个」），用户**只否决错的**，落盘即普通事实；未过目的不落盘。不复用 `✓` / `待核实`——`✓` 的定义是「事实取自**这一页 URL**」，简历不是 URL，套上去当场污染二元标记的含义；也不新设第三种标记，那撞 [ADR 0001](0001-evidence-stays-binary-with-a-closed-suffix.md)。理由是：**用户确认这个动作本身就是这条线上的取证**，它完成的那一刻，标记就没有指称对象了。落一个「待用户确认」等于把一件只能在对话里解决的事永久化成待办，正是 [ADR 0009](0009-safer-is-defined-by-the-programs-second-published-line.md) 拒绝把「第二条线查不到」并进缺口清单的同一条理由：**永远勾不掉的待办**。

**用户不知道方向时，产品说出来。** 这是唯一一个镜子照不出东西的场景：`programs.md` 空 → 没有项目 → 没有页面可取回 → 整台机器点不着火。此时**明说「选方向这一步我给不了依据」**，并把它转成用户可执行的最小动作（贴 3 个项目链接回来 / 说 3 个听过的学校名），产品从那一刻接手取证。不做引导式收敛——那产出的每一句都是零依据判断，撞 [#11](https://github.com/jiangxidong/EduApplication/issues/11) 的「结论 + 依据 + 作废条件，写不满就不写」。也不给起步清单——撞硬编码院校库（Out of scope）与停手线取证类。

## Consequences

**放弃的是留存率最高的那一屏，代价要明写。** 首屏给出「我读懂了你」比给出「你该申这 8 所」弱——后者是竞品都在做的钩子。本决定明知这一点仍然选前者，因为另一条路上第一屏就要撒谎，而**申请这件事撒一次谎的代价落在一整个申请季上**。将来有人拿着留存率数字想把选校草案加回首屏时，需要读到的是这一页，而不是重新发现一遍。

**这条纪律是可执行的，不是一句愿望。** 判据不是「草案好不好」，是**这条断言的两个半句各来自哪里**：讲申请人的半句，真相源是用户，首屏可写；讲学校的半句，真相源是官网，本会话零取回，首屏不可写。这与 [#18](https://github.com/jiangxidong/EduApplication/issues/18) 给 why 段定的两道闸是同一台机器——同一句话里的两个半句走两条不同的闸。

**「先抽后问」因此在冷启动需要一条例外，已随本决定落下。** [#10](https://github.com/jiangxidong/EduApplication/issues/10) 承诺读了再问，[#19](https://github.com/jiangxidong/EduApplication/issues/19) 定了槽位先于文件且不预建空目录——冷启动时工作区不存在，简历不在任何槽位里，两条硬碰。解法是**逐文件交接**：用户一次给一个文件并声明它是什么，agent 按声明的敏感级决定读不读，**绝不扫描目录**。载体从路径换成用户声明，两条同时成立，且 agent 从不扫描意味着误读的物理前提不成立——而误读是产品里唯一不可补救的越界。

**它不保证首屏够抓人。** 镜子照得准不准，全看抽取质量；用户不带任何材料来时，镜子里几乎是空的，第一屏退化成四个问题（本科学校 / 专业 / GPA / 语言分）。这是本决定的软肋，没有结构性对策——只能靠抽取做得好，以及靠第 0 问明写的那条「我还不知道要申什么」把最坏的情况变成一条明路而不是一次卡死。
