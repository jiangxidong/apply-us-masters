# 词汇表定义词，契约持有取值

> ⚠️ **找《准备包整包重生成，绝不就地改》的读者请走这边**：那一条也曾叫 ADR 0011，已改号为 [ADR 0013](0013-a-packet-is-regenerated-whole-never-patched.md)（详见该文件的「原编号」一行）。[#8](https://github.com/jiangxidong/EduApplication/issues/8) 评论里**改号之前**的「ADR 0011」（两条死链 + 两处裸引用）指的是**它**，不是本条——两条讲的是完全不同的决策，照号找到本条是**静默的走错门**，不会报错。（**例外**：#8 里记录改号那条评论写的「ADR 0011」确指本条，别把它一并改读。）

[#23](https://github.com/jiangxidong/EduApplication/issues/23) §7 锁定「归属表是状态层契约里**唯一一张**『路径 / 节 → 阶段』表，`CONTEXT.md` 只定义词、不承载表」。而 #23 落盘时，把整张十节归属表连同 owner 列写进了 `CONTEXT.md` 的「节」词条——**决议与它自己的落盘不一致**，正是 [#18](https://github.com/jiangxidong/EduApplication/issues/18) 点名、#23 立规矩要防的那件事，发生在立规矩的同一次提交里。

这不是执行失误。`CONTEXT.md` 的开篇**在 #23 之前**就写着「本文件只定义词……实现细节一律不进这里」，#23 是照着这句话写的表。病灶是那句话本身：**「实现细节」不可判定**。一张表算不算实现细节，取决于谁在什么心情下读它，所以它拦不住任何东西——一条没有判据的边界，等于没有边界。

## 决定

**两条判据决定一行字属于词汇表还是契约。** 两条都不是新发明，都是把产品内部已经验证过的机器抬一层用在 repo 文档上——这正是 [ADR 0008](0008-the-owner-binds-to-a-section-not-a-file.md) 那一刀之所以站得住的同一个理由。

1. **镜像判别式**（取自状态层契约判工作区文件的那条）：**这行字为了保持为真，需不需要在别处改动时被改写？需要 → 它是镜像，不写在词汇表。**
2. **消费方判据**（取自 #23 判 owner 归属的那条，抬一层）：**agent 在什么时刻读它？** 命名领域概念时 → 词汇表；决定一条事实落进哪个文件、哪个节、谁能写 → 契约。

两条是**接力**不是竞争：① 答「要不要存两处」，② 答「唯一那处在哪」。

**引用配额**：完全禁止引用会逼出更坏的东西——读不懂的规则，下一个 session 会去别处再抄一份。所以允许引用，但**引用处不写全枚举**，只举用得着的那几项并带指针。形态本身就在说「我不是权威」。「完整」可脚本判定：词表在契约里，数一下引用覆盖了几项。

## 被否掉的三条

**「有 owner 列 = 归属表 = 只许一份」。** 精确对准 #23 §7 的原话，但太窄：管不了 `documents/` 七槽位那种「同一批事实的两个视角」，更管不了 `tier` 那种「散文里抄了全枚举」——那处不是列，任何窄禁令都拦不住。

**「允许重复，但脚本校验两处一致」。** 它把漂移从不可见变成可检出，却承认了漂移的存在。而判据 ① 说的是这行字**根本不该有第二份**。这类补丁正是 #23 否掉的形态。

**「内涵 / 外延：凡带 `v1` 版本限定的枚举归契约」。** 有诱惑力，因为 `CONTEXT.md` 自己写着「v1 十个法定节」「v1 七个槽位」，那个 `v1` 像是自供状。但它会把 `tier` 五档判进契约，而 `reach` / `safer` **各自就是词条**——判错。降级为判据 ① 的一条提示：看见 `v1` 就该警觉。

## Consequences

**四处重复按判据落位，其中一处方向是反的。** 实测（逐词比对 `CONTEXT.md` 与 `CONTRACT.md`）重复恰好四处，比 [#26](https://github.com/jiangxidong/EduApplication/issues/26) 票面猜的少——停手线三类十条与三个样例档案都只有一份：

| 内容 | 归 |
|---|---|
| 十节 → owner 表 | **契约**，`CONTEXT.md` 的「节」词条只留机制 |
| `documents/` 七槽位 | **拆列**：中文 ↔ 标识符留词汇表，目录形状 / 逐院校 / 敏感级归契约 |
| `tier` 五档 | **词汇表**——方向与前两处相反 |
| 「节」词条里三条契约条款散文 | **契约** |

`tier` 的反向不是例外，恰恰是判据在起作用的证据：owner 是契约的内容，而五个档各自是**词**。同一条机器把两样东西推向相反的方向，说明它切的是真关节。

**封闭词表整个走契约，不留在词汇表。** 这推翻了一个看起来更自然的拆法（词表留词汇表、只搬 owner 列）。两条判据都指向反面：`CONTEXT.md` 的十节顺序**不是任意的**，它是 owner 分组的顺序（选校×5 → 文书×2 → 材料 → 推荐信 → 准备包），而 ADR 0008 第 4 条检查是「节按词表顺序排列」——owner 一变顺序就得改，**有序词表是 owner 表的镜像**；而 agent 从来不需要「全部十个节名」，它在写 `##` 标题那一刻要的是「我这个阶段能写哪几个节」，词表与 owner 列在使用现场不可分，拆开会造出一个没有任何消费者的产物。

**指针会成环，必须显式拆。** `CONTRACT.md` 开头写着「术语以 main 分支的 `CONTEXT.md` 为准」；`CONTEXT.md` 现在反过来指契约。环按**范围**拆而不按文件拆：**词的定义以 `CONTEXT.md` 为准，v1 的取值与归属以状态层契约为准**——两句话各管一半，不重叠。

**`main` 上那个链接是死的，且明写出来。** `CONTRACT.md` 住在未合并的 `prototype/state-layer` 分支，`CONTEXT.md` 指向它的路径链接在 `main` 上解析不到。地图 Notes 已经记着这个坑栽过一次（#22 的产出关票后长期未提交、地图链接是死的）。显式承认远好过假装：`CONTEXT.md` 里注明分支与未合并状态，并给出 `main` 上唯一可达的入口（#4 的回填评论）。合并后自愈。

**执法仍然是欠的，而且欠得比想象中多。** 本决定给出的机械形态有两条——`CONTEXT.md` 里不得出现 owner / 阶段列；引用处不得出现完整枚举——它们本该并入 ADR 0008 的孤儿检查清单成为第 7、8 条。但查证发现：**那份「六条检查」从来没有实现，一行代码都没有**（`prototype/state-layer` 上唯一的 `.sh` 是 `derive-demo.sh`，其中没有任何节 / owner 检查）。往一份从未被执行过的散文清单里再加两行散文，与本 ADR 要治的病同构。检查以什么形态存在、谁在什么时刻触发，另开票判。

**反向不可逆的代价是中等。** 判据一旦成为全产品判文档归属的机器，改判据要重扫所有文档。但四处落位本身可逆——搬回来是四次编辑。真正难回头的是判据，不是位置。

## 后续

[#28](https://github.com/jiangxidong/EduApplication/issues/28) **取消了「节按词表顺序排列」这条规则**（`CONTRACT.md` §1.2；[ADR 0008](0008-the-owner-binds-to-a-section-not-a-file.md) 的 `## 后续` 里删掉了对应的第 4 条检查）。理由是它不定任何 owner、只买 diff 稳定，却要求后到的 owner **插入**而不是追加——`## 项目内容`（第 6）得插进选校的 `硬约束`（2）与准备包的 `材料上传`（8）之间。

**本 ADR「封闭词表整个走契约」那一段的两条理由，第一条随之作废**：

- ❌ **镜像那半作废。** 原文说「`CONTEXT.md` 的十节顺序不是任意的，它是 owner 分组的顺序……而 ADR 0008 第 4 条检查是『节按词表顺序排列』——owner 一变顺序就得改，**有序词表是 owner 表的镜像**」。第 4 条检查没有了，**词表也不再是有序的**，这条镜像论证失去了它的支点。
- ✅ **结论不变，靠第二条理由独立成立**：agent 从来不需要「全部十个节名」，它在写 `##` 标题那一刻要的是「**我这个阶段能写哪几个节**」——词表与 owner 列在使用现场不可分，拆开会造出一个没有任何消费者的产物。

**正文一字未改**（照 [ADR 0004](0004-tiers-are-anchored-on-published-hard-requirements.md) 的先例）。⚠️ 但要留意：本 ADR 的判据是「**这行字为了保持为真，需不需要在别处改动时被改写？**」——而它自己这段论证正是因为别处（ADR 0008 第 4 条）改动而失真。**一条论证也可能是镜像**，不只是数据。

✅ **序号撞车已结案，由 [ADR 0016](0016-the-checklist-holds-names-and-pointers.md)（[#35](https://github.com/jiangxidong/EduApplication/issues/35)）。** 上面「Consequences」末段说本 ADR 的两条机械形态「本该并入 ADR 0008 的孤儿检查清单成为**第 7、8 条**」——**那两个号最后一个都没拿到**：第 7 条被 [#25](https://github.com/jiangxidong/EduApplication/issues/25) 用掉（多写入者路径的切法必须已声明），第 8 条被 [#37](https://github.com/jiangxidong/EduApplication/issues/37) 用掉（季度戳表的键），两次都发生在 #35 开着的时候。

**序号整个废除，改稳定短名。** 本 ADR 这两条机械形态现在叫 `glossary-holds-no-owner` 与 `citation-is-partial`，规则原文仍以本文「决定」①② 与「引用配额」为准；名字、被测对象与归属见 [`docs/checks.md`](../checks.md)。**正文那句「第 7、8 条」不再指任何东西**，照 ADR 0004 的先例正文一字未改，此处作废它。

⚠️ 顺带：Consequences 末段那句「那份『六条检查』从来没有实现，一行代码都没有」**至今仍然为真**——ADR 0016 定的是形态与归属，不是实现。

### #42：「引用配额」的判据——花在会判错的项上，不花在有哪些项上

本 ADR 的引用配额只说到「允许引用，但**引用处不写全枚举**，只举**用得着的那几项**并带指针」就停了——**「用得着」没有判据**。[#42](https://github.com/jiangxidong/EduApplication/issues/42) 把它用在 `CONTEXT.md`「派生视图」词条那份名单上时补出下面四句。**正文一字未改**（照 [ADR 0004](0004-tiers-are-anchored-on-published-hard-requirements.md) 与本文 #28 那节的先例）。

**① 判据 = 把消费方判据再用一次。** 本文说两条判据是**接力**：① 答「要不要存两处」，② 答「唯一那处在哪」。引用配额是接力的第三棒，用的还是第二条那把尺子——**agent 读一个词条的时刻**是「我手上这行字该不该落盘」，那一刻它要的是判别式加**会判错的边界例**；「有哪些项」的消费时刻是「v1 要实现哪些视图」，那是契约。所以：

> **引用配额花在「读判别式时会判错的那几项」上，不花在「有哪些项」上。**

落到「派生视图」词条是**正例零项**。保留的三处全是反例——`recommenders.md` 的「主张 → 推荐人分配」与 `tier_basis`（会被改写，但不是任何别处的镜像，见 [#12](https://github.com/jiangxidong/EduApplication/issues/12) 补的前提句）、`essays/canonical/`（[#32](https://github.com/jiangxidong/EduApplication/issues/32) 补的限定句那一例）——**没有一项在 `CONTRACT.md` §1.5 的名单里**。本文担心的「完全禁止引用会逼出读不懂的规则」在这里不成立：**教学载荷由反例扛，不由花名册扛**。

**② 归属声明的落位：「X 是派生视图」住 X 自己的词条。** 这一句是零正例能成立的另一半。`选校清单` / `投递名单` / `缺口清单` 三个词条**自己就写着「派生视图」**，那不是名单的副本——「它是池子的一个过滤视图」是这个词的**内涵**，是定义本身；被推导出来的是名单，不是反过来。例子因此没有消失，它们**分散住在各自的词条里**。

**③ 于是三样东西各答一个问题，死掉的是夹在中间那一份。**

| 产物 | 答的问题 |
|---|---|
| 词条 | 这个词是什么（**含它是不是派生视图**） |
| `CONTRACT.md` §1.5 名单 | **v1 要实现哪些**（外延闭合；其中 7 项在词汇表里没有词条，从词汇表推不出来） |
| ~~词汇表里的第二张花名册~~ | **无**——每新增一个视图就要跟着改，正是判据 ① 判死的形态 |

**④ ADR 里的复述不是镜像。** [ADR 0002](0002-one-program-pool-one-status-axis.md) 第 5 行同样写着「『选校清单』与『投递名单』……是**派生视图**，不落盘」。**不动它**：ADR 是取证记录、正文不随后续改（本周三次先例——本文由 #28、[ADR 0005](0005-basis-points-at-an-existing-checked-fact.md) 由 [#36](https://github.com/jiangxidong/EduApplication/issues/36)、[ADR 0006](0006-claims-are-one-shared-truth-source.md) 由 #32，全是补节），它记的是「当时是这么判的」，与 `CONTRACT.md` §1.5 给 `log.md` 的**历史观察值**豁免同构。⚠️ 少这一句，下一个拿判别式扫 repo 的人会去「修」ADR 正文。

**⑤ 可判形态因此变了，而且变简单了。** 本文原来设想的是「词表在契约里，**数一下引用覆盖了几项**」。判成零正例之后不必再数：

> [`citation-is-partial`](../checks.md) 落到本例的形态：**`CONTEXT.md` 的「派生视图」词条正文内，不得出现 `CONTRACT.md` §1.5 名单中任何一项的名字。** 纯 `grep` 可判，三处反例都不在名单里，**不需要白名单**。

✅ **这条规则第一次跑就咬到了本节自己的初稿。** #42 落盘时，那句归属指针原本写成「写在 **X 自己的词条**（见「待核实清单」「缺口清单」「选校清单」「投递名单」）」——手跑一遍当场 4 处 FAIL。**举「哪几个词条有这句话」和举「有哪些视图」是同一份花名册**，只是换了个说法。已删成不点名的形态。

`docs/checks.md` **不新增行**——[ADR 0016](0016-the-checklist-holds-names-and-pointers.md) 已经给这条规则起过短名 `citation-is-partial` 并指向本文的「引用配额」，本节是同一条规则的原文变精确，不是第二条检查。⚠️ 本票**不造检查器**：`evals/checks/check-docs.sh` 至今不存在（`evals/` 整个目录都没有），而往一份从未被执行过的清单里再加一行散文，正是本文 Consequences 末段说过的、与本 ADR 要治的病同构的形态。
