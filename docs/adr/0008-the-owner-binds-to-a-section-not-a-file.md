# 唯一写入者绑定的是「节」，不是「文件」

[#9](https://github.com/jiangxidong/EduApplication/issues/9) 锁定了 **owner = 唯一写入者，跨 owner 的写一律禁止**，并把 [#4](https://github.com/jiangxidong/EduApplication/issues/4) 的 11 个文件分给了 4 个 skill。这条规则在 `channels/<channel_key>.md` 上当场不成立——而且不成立的痕迹就写在 #9 自己的表里：那一栏填的是「`channels/` **骨架**」与「`channels/` **补全**」，已经在用细于文件的限定词，只是没给判据。

三处独立地撞上同一堵墙：#4 的契约原文就是两阶段写入（选校期落骨架、准备期补全）；[#18](https://github.com/jiangxidong/EduApplication/issues/18) §5 又加了第三类内容（why 段的具名事实必须先落 `channels/`），而消费方 `write-essays` 不是 owner，#18 只好把它转成缺口清单并留下「谁去填」的空白；[#12](https://github.com/jiangxidong/EduApplication/issues/12) 新增的 `recommenders/drafts/` 则整个不在 owner 表里。

最自然的补救有两条，都被否决。**把 `channels/` 定成「例外」**——例外没有判据就会蔓延，而「什么样的文件可以有多个写入者」本身没有机械判据，只能每次开会拍板。**把 `channels/` 拆成两个文件让每个回到单 owner**——它的唯一收益是「单 owner per file」，而那恰恰是本决定要放弃的东西；且按新判据 `channels/` 是三个 owner 不是两个，拆两个根本不够，拆三个会把 UIUC 的「学历门槛」与「文书规格」劈开，用户看一所学校的约束要开三个文件。

决定：**唯一写入者绑定的单位是节，不是文件。** 一个文件有几个写入者不需要辩护；需要辩护的只有两件事，且都禁止：**一个节有两个写入者**、**一条事实找不到写入者**。

支撑这一刀的是对「这条规则到底防什么」的重新定位。它防的**不是写冲突**——agent 运行时是单会话串行的，两个 skill 物理上不会并发写同一文件；「一个文件一个写入者」是从多人协作代码库借来的直觉，在本产品里没有对应的失效模式。它防的是**责任漂移**：同一条事实由两处各自维护、各自更新，必然不一致。而漂移的单位是事实，不是文件。

由此归属判据也定了：**消费方**——哪个阶段的决策依赖这条事实，哪个阶段就负责取证并落盘，多消费方归最早的那个。否决「时序」判据（即 `骨架 / 补全`）是因为它循环：「什么时候被填」恰恰是要定的东西，拿它当判据等于没答。否决「主题」判据是因为它定不了归属——「文书规格」按主题属约束层，但约束层整体没有单一 owner。

owner 绑**阶段**而非 skill：阶段是内容的自然切分，skill 是分发的打包，会因触发面与 description 截断而重排（#12 的作废条件就明说过 `assemble-packet` 可能要重拆）。绑阶段则重拆 skill 时归属表一行不动。

## Consequences

**`channels/` 有三个阶段 owner，而多出来的那个正是 #18 缺的那个。** 十个法定节按消费方切成选校（平台与账号 / 硬约束 / 学历门槛 / 费用与资格 / AI 使用政策）、文书（**项目内容** / 文书规格）、准备包（材料上传 / 推荐信机制 / 冻结点）。`项目内容` 是本决定新增的第 10 节——#18 之所以留下「谁去填这个缺口」的空白，根因是它要落的那批具名事实（课程号 / 教授 / 实验室）**不属于原有 9 类中的任何一个**：它们不是约束，是项目本身的内容。缺口不是没人负责，是**没有类别**。

**节必须可被机械识别，代价是引入一条封闭词表。** 实测三份样例，节集合逐渠道不同、标题带自由后缀（`## 材料上传 —— ⚠️ 与 Cornell 直接冲突`）。规则取「封闭词表 + 前缀匹配 + 禁止互为前缀」，而不是「标题逐字相等」——那些后缀是跨渠道冲突的现场记录，是 ADR 级别的信息，不该为了机械匹配丢掉。

**防蔓延从「不可判定」变成「可脚本化」。** 原问法（什么样的文件可以有多个写入者）没有机械判据；新问法的两个禁止项都能被检出。孤儿检查脚本因此多出几条机械判据。🔴 **此处原本是一串按序号排的枚举，已删除**——检查不再用序号说话，也不在本文复述：名字、被测对象与规则原文的归属见 [`docs/checks.md`](../checks.md)（[ADR 0016](0016-the-checklist-holds-names-and-pointers.md)）。本决定产出的是 `path-resolves-to-owner`、`section-prefix-match`、`vocab-item-one-stage`、`drafts-imply-consent`、`subsection-under-program`；原第六条「节按词表顺序排列」已被 [#28](https://github.com/jiangxidong/EduApplication/issues/28) 删除并换成 `overlay-no-bare-lines`。仍不进 CI。

**换季降级必须改成惰性执行。** 由入口阶段一次性全表降级会构成跨 owner 的写——这是本决定挖出的、#4 与 #9 都没发现的第二个无主动作。改成「各阶段下次进入时按文件 frontmatter 的 `season` 比对，就地降级自己的节」。判据现成（原型样例已有 `season: 2027fall`），且未被访问的节保持上季标记比假装重查过更诚实。代价是派生视图要在渲染时按 `season` 比对，不能只看标记。

**归属表从 #9 的表里搬走，#9 需要一条更正。** 归属表只有一份，住在状态层契约里；#9 的表降级为「阶段 → skill」映射，不再出现任何路径字面量。这是 #4 §0「不得再出现第二个路径字面量」的延伸——现在它管的不只是工作区根，还有工作区内的每个路径。

**反向不可逆。** 一旦允许多写入者共存于一个文件，收回「一文件一 owner」意味着重切 `channels/` 的文件布局，并连带改 #4 的文件清单与 `channel_key` 语义。若将来出现真正并发的写入者（多 agent 并行跑同一工作区），排除「写冲突」的理由作废，这一刀需要重算。

## 2026-08-15 修订（#25）：三条限定

[#25](https://github.com/jiangxidong/EduApplication/issues/25) 裁决 [#24](https://github.com/jiangxidong/EduApplication/issues/24) 合并 `CONTRACT.md` §1 时查出的三处例外（`programs.md` 的 `status` 列 / `materials/` 双 owner / `log.md` 全阶段追加）。它们的共同问法是「一个不含节结构的文件被两个阶段写，算不算破例」——而「破例」这个框本身是错的：两处按本文现有判据直接就有唯一解，一处压根不在本文辖区内。

🔴 **本节修订的是上面的决定句，不只是补 Consequences。** 标题与文件名不变——「节 vs 文件」这一刀仍然成立，只是「节」被认成**实例**而非规则本身。

### 限定 1 — 绑定单位是「该文件格式自己的结构单元」

本文正文写的是「漂移的单位是**事实**，不是文件」，落成规则时却写成「一个**节**两个写入者」。「节」是散文文件的形态产物；一旦被当成规则本身，每种非散文文件都得逐个开例外——而「例外没有判据就会蔓延」正是本文拒绝把 `channels/` 定成例外的理由。本文踩了自己那条。

> **唯一写入者绑定的单位是该文件格式自己的结构单元。** 散文文件是**节**，表格是**列**，`documents/` 是**槽位**。两条禁止项一字不变：**一个结构单元两个写入者**（禁止）、**一条事实找不到写入者**（禁止）。归属判据仍是**消费方**。

配一条防蔓延闸，否则「一个单元两个写入者」永远能靠把单元切细来规避，规则归零：

> **切法必须来自契约里预先声明、脚本能枚举的结构。不许临时发明切法。** 当前已声明的切法有**三种**：`channels/` 的十节封闭词表、`claims.md` 的行（限定 2）、`programs.md` 的 13 列（`CONTRACT.md` §4.6）。

✅ **「列」已有现货**（[#59](https://github.com/jiangxidong/EduApplication/issues/59)）：`CONTRACT.md` **§4.6「`programs.md` 的 13 列（唯一完整列举处）」** 已落盘，本条原写于它之前，那句「没有一处完整列举」**已作废**。
⚠️ **有名单 ≠ 已按列切分**——§4.6 自陈「本节是**声明**，不是切分」，而 [#25](https://github.com/jiangxidong/EduApplication/issues/25) 已判 `programs.md` 单 owner = 选校、13 列含 `status` 无例外。

### 限定 2 — owner 可沿生命周期**单向移交**，闸门是「不可回流」

这条是被 `claims.md` 逼出来的。[#23](https://github.com/jiangxidong/EduApplication/issues/23) 把它（冷启动/画像落初稿、文书打磨）认成第二个多写入者文件，说它「与 `channels/` 完全同构」——**它不同构**。`channels/` 按节切，节是封闭词表；`claims.md` 按**生命周期两端**切，那正是上面否决掉的**时序判据**。#23 认可了它，却从没给过它判据。

> **owner 可以随生命周期从阶段 A 移交给 B，条件是：任一时刻仍然唯一，且 A 此后永不再写（不可回流）。**

与被否决的时序判据的区别是要害：**时序判据拿「先填后填」当归属依据**（循环——「什么时候被填」恰恰是要定的东西）；**移交承认归属会变，但要求变化不可逆**，因此「谁负责让这条事实保持为真」在任何时刻都有唯一答案。防的仍是责任漂移。

**唯一实例，也是它的证明**——`claims.md` 在文件粒度上过不了「不可回流」（画像阶段可重入；[#21](https://github.com/jiangxidong/EduApplication/issues/21) 明写措辞会被文书反复改写；`voice` 列 #21 没说谁写，撞第二条禁止项）。换成**行**做移交单位，三条全部消解：

> **移交单位是「一行」，方向 画像 → 文书，发生在行诞生的那一刻。** 冷启动/画像只 append 新行（`materials` 留空——#21 已定「允许零素材主张，那正是缺口本身」），**从不改已有行**；此后这一行的全部写入权归文书，而文书**从不 append**（#21 已定「文书从『发明主张』改为『从主张清单里选』」）。

`claims.md` 的正当性因此来自本限定，**不来自 #23 的「与 `channels/` 同构」**——那句话作废。

### 限定 3 — 辖区条款：owner 只管**会被改写**的内容

> **append-only 且从不被改写的内容，不在本文辖区内**——不需要 owner，也不构成破例。

理由是本文自己的：它防的是**责任漂移**，而漂移必须**经由改写**发生。从不被改写的内容里没有「保持为真」这项责任，也就没有可漂移的对象。这条推理契约里已经在用，本限定只是把它从镜像规则推广到 owner 规则：`CONTRACT.md` §1.5 的镜像豁免（「`log.md` 从不被改写，所以它记的是历史观察值不是镜像」），以及上面「换季降级必须改成惰性执行」反过来用它否掉降级的类比（「援引它是拿反了，**降级就是改写**」）。

`log.md` 因此不是破例——规则管不到它。附带解释了样例里明摆着的一件事：它的**分段单位是「会话」不是「阶段」**，而一个会话可以跨多个阶段；按原规则这当场违规，按本限定**分段单位根本不参与判定**。

否决「给它一个 `所有阶段` 的 owner 值」：那是把「无 owner」改写成「owner = 全体」，字面上过检查，但这个值一旦存在就是**没有判据的万能出口**。否决「写一条 `log.md` 专属豁免」：本限定说的是**规则的辖区**（可复用、有判据），专属豁免说的是**这个文件特殊**（不可复用）。

### 检查表：改写一条、新增一条

🔴 `path-resolves-to-owner` 原本会把 `log.md` 判成违规——只改叙述不改检查，限定 3 等于没落地。

- **`path-resolves-to-owner` 改写**：契约里出现的每个路径，**要么**解析到一个 owner 阶段（自身或祖先目录），**要么**在归属表的 owner 列被标成 `append-only`。`append-only` 是**封闭标记**，当前唯一持有者是 `log.md`；新增持有者必须在同一次提交里给出「从不被改写」的论证。
- **新增 `split-is-declared`**（限定 1 的防蔓延闸）：每个多写入者的路径，其切法必须是契约里**已声明且脚本能枚举**的结构。当前合法切法有**三种**：`channels/` 的十节封闭词表、`claims.md` 的行、`programs.md` 的 13 列（`CONTRACT.md` §4.6）。**切法未声明 = 违规。**
- 仍不进 CI。

🔴 **`claims.md` 的 append/rewrite 分工不进检查表——它不是检查，是规则。** 验它要 commit range，而**工作区不是 git 仓库，没有 diff 可跑，也没有「这次写入属于哪个阶段」这项元数据**。它是写给 skill 的行为规则，靠契约措辞约束，不靠脚本。写明于此，免得下一个 session 以为它被机械保护着。**本限定落盘时未经验证**，且在 v1 里不可机械验证——这是本 ADR 尾部那条「转述过 ≠ 核过」的同一条纪律。

## 2026-08-15 修订（[#37](https://github.com/jiangxidong/EduApplication/issues/37)）：限定 4 — 记录 owner 状态的戳，跟着 owner 走

[#23](https://github.com/jiangxidong/EduApplication/issues/23) 依本文把 owner 从「文件」翻到「节」，却把**换季降级的季度戳留在了文件级**：

> 各阶段下次进入时，发现自己 owner 的节所在文件 frontmatter 的 `season` ≠ 当前 `season`，才就地降级自己的节，**并同步该文件的 `season`**。

一个 `channels/*.md` 有五个阶段 owner，于是选校先进来、降完自己那 5 节、把文件 `season` 刷成本季之后，**文书再进来就不匹配失败，永远不降自己那 2 节**——它们带着上一季的 `✓` 无限期留存，而文件的 `season` 声称它是本季的。陈旧因此**不是一个会关闭的窗口，而是被第一个进来的阶段永久掩盖**，且 `CONTEXT.md`「降级」词条那条「派生视图按 `season` 比对」的渲染规则在这种情况下也是瞎的。

这是本文已经纠正过一次的**同一个范畴错误**，只是换了个对象：owner 绑节不绑文件，那么「这个 owner 降级到哪一季了」这个戳也必须绑 owner。

> **限定 4：凡记录「某个 owner 对自己辖区做了什么」的状态戳，其粒度必须与 owner 绑定的粒度一致，不得挂在文件上。**

落到换季降级：文件级 `season` 字段**删除**，改为 frontmatter 里的一张 **`season_downgraded`** 表，键取自封闭的「阶段」词表，各阶段只戳自己那行。`programs.md` 因此**新建 frontmatter**（它此前一行 frontmatter 都没有，所以惰性降级在它身上**根本无法执行**——而 `deadline` 的取证状态恰恰只住在它的 `evidence` 列），表里只有一行（选校）。**不为单 owner 文件开「用标量」的第二条判据**：检查脚本要为两种形态各写一遍，而本文自己就是从「文件」翻到「节」的——「今天只有一个 owner」不是可以刻进契约的性质。

**这张表不是镜像。** 它记的是「某个 owner 在哪一季对自己辖区做完了降级」，是历史观察值，同 `log.md` 与 `source_fingerprint` 的豁免（亦即限定 3 的同一条推理：它从不为了保持为真而被改写）。

🔴 **连带必须同时成立：建节即戳，降级即戳。** 一个 owner 在某文件里**落下第一个节的同时**就戳上当季，此后每次降级重戳。选校在 2027fall 新建 `channels/x.md` 并当场取证打 `✓`，若不同时写 `season_downgraded: {选校: 2027fall}`，那批**刚刚取回的**事实会立刻被判成陈旧——最新鲜的证据当成最陈旧的。

**缺行 = 该 owner 在本文件里没有内容，不是陈旧。** 「建节即戳」使**有内容 ⟺ 有行**，所以缺行只能读作「它一个节都没落过」——没有节，就没有要渲染的东西，也就无所谓陈不陈旧。

> ⚠️ **这一条曾被写反过一版**（[#37](https://github.com/jiangxidong/EduApplication/issues/37) 落盘时写的是「缺行 = 陈旧（fail-safe）」，[\`efa8318\`](https://github.com/jiangxidong/EduApplication/commit/efa8318)），在**首季工作区**上当场破：新建的 `channels/x.md` 里文书从没落过节，按那一版它的行缺席 = 陈旧，包会把 `## 文书规格` 渲染成一个引用「上季核过」链接的 ⬜——**而首季根本没有上一季，那个链接不存在**。同一版的 `season-stamp-matches-owners` 还要求键**恰好等于契约的 owner 集合**，那等于逼建档的选校替另外四个阶段预先写行：既是本文明令禁止的**跨 owner 的写**，又是 [#23](https://github.com/jiangxidong/EduApplication/issues/23) 否掉的**预建空节**。两处一并更正如上。

**fail-safe 由 `season-stamp-matches-owners` 守，不由「缺行」的读法守**：漏戳会被检查判成违规，而不是被静默读成本季。

### 检查表：新增一条

只改叙述不改检查，限定 4 等于没落地（同限定 3 的教训）。

- **新增 `season-stamp-matches-owners`**：契约里每个承载证据标记（`✓` / `待核实`）的路径，其 frontmatter 必须有 `season_downgraded` 表，且该表的键**恰好等于「在该文件里实际有内容的 owner」集合**——这个集合由**文件内容 + 归属表机械推出**（逐节剥离前缀匹配到法定节名，再查 owner），不是照抄契约的 owner 名单。**有内容而无戳 = 违规**（这是 fail-safe 那一半：漏戳被检出，而不是被读成本季）；**有戳而无内容 = 违规**（预建空行，同 #23 否掉的预建空节）。**文件级 `season` 字段出现在这类路径上即违规。**
- 仍不进 CI（同上）。

⚠️ **本限定落盘时，`CONTRACT.md` 侧尚未跟改**——它只活在 prototype 分支，而落盘时仓库根这一个 checkout 在 `main` 上、另有四个 worktree 活着，切分支会搅到别的 session。契约侧与样例侧的改动转 [#47](https://github.com/jiangxidong/EduApplication/issues/47)。**在 #47 落盘之前，`CONTRACT.md` §4 与本节直接冲突，以本节为准。**

## 2026-08-15 修订（[#44](https://github.com/jiangxidong/EduApplication/issues/44)）：限定 5 — 「现有单元都收不下」必须引用原文，不能引用转述

[#44](https://github.com/jiangxidong/EduApplication/issues/44) 立票的判断是「STEM / CIP 这条事实，十个法定节一个都不收它」，据此要开第 11 个节。**这个判断不成立，而它不成立的方式值得刻进本文**——它是本文两条禁止里第二条（「一条事实找不到写入者」）**被误报**的第一例。

查证（`git grep -n '费用与资格' main prototype/state-layer prototype/program-shortlist prototype/application-packet -- '*.md' | grep -v sample-workspace`——**四份副本一次扫全**，因为 [#46](https://github.com/jiangxidong/EduApplication/issues/46) 已证实 `prototype/application-packet` 自带一份落后一整轮的 `CONTRACT.md`，而**落后的范围话仍然是「写下来的」范围话**）：`prototype/application-packet` 的三行与 `state-layer` 逐字相同，`prototype/program-shortlist` 零命中，**没有任何一份副本给 `费用与资格` 划过上界**。唯一一句范围话是 `CONTRACT.md` §1.2 的 🔒「费用类事实的唯一去处是 `费用与资格`，`硬约束` 不收」，而它的方向是**反的**——它约束 `硬约束` 收什么，从没说 `费用与资格` 只收费用类。票面那句「`费用与资格` 收**钱与减免资格**」是立票人自己的转述。节名字面就带「资格」二字；而三个样例 channel 文件**各自独立地**把 `` `待核实` STEM OPT 资格 `` 填进了 `## 费用与资格`——一个人在这个节名下毫不犹豫地填了三次。（样例只需过结构那一关（[ADR 0010](0010-personas-ignite-assertions-they-are-not-examples.md)），所以它不是归属权威；它是一份**读者行为**证据。）

> **限定 5：援引「现有每一个结构单元都收不下这条事实」来给封闭词表加项时，每一个「收不下」必须引用一句写下来的范围话。被援引的单元若还没有范围话，先把范围话补上，再谈加项。**

**它防的是本文自己挖的坑。** 封闭词表是本文为了「节可被机械识别」引入的，而本文给了词表**十一项的值，从没给过任何一项范围**。于是「这条事实属不属于这一节」在契约里没有原文可查，只能由每个 session 现场从节名重新想象一遍——两个 session（[#34](https://github.com/jiangxidong/EduApplication/issues/34) 与 #44）连续从同一次想象里判出「该开第 11 个节」。**没有范围话时，「收不下」不是一个判断，是一次转述。**

**成本摊在敲门的时候。** 否决「一次性给现有十一项全部补上范围话」：那是一次全契约改写，而**多数项至今没人来敲过门**，替未来的争议预写范围话大概率写偏。

本节自己是证据，而**它不是第一例**：十一项里在此之前唯一有范围话的是 `硬约束`（§1.2 的 🔒「`硬约束` 装的是「每学期只能申 1 个项目」「禁止本人以外代交」这类流程性限制」），而那句话也是**被敲门敲出来的**——它出现在「费用类事实的唯一去处是 `费用与资格`」同一句里，写于样例的一条申请费事实在两节里各存一份、撞上责任漂移的时候（归 [#27](https://github.com/jiangxidong/EduApplication/issues/27)）。**两次都是先有争议、后有范围话，而不是反过来。**

限定 5 因此只要求：谁要动词表，谁顺手给被援引的那节留下一句以后可被援引的原文。

**它与「缺的不是人、是类别」不是同一个形态，尽管两次都以「收不下」开场。** [#23](https://github.com/jiangxidong/EduApplication/issues/23) 那次是真的缺类别——`项目内容` 要装的课程号 / 教授 / 实验室**不是约束**，原有九类无一在语义上覆盖它。本次不缺类别，缺的是一句写下来的范围话。#44 票面把两次认成同形（并据此要重判「封闭词表该怎么长」），正是因为**这两种情形在没有范围话时长得一模一样**。限定 5 就是把它们分开的那一刀。

### 本次的落地：不开第 11 个节

`费用与资格` 补一句范围话，STEM / CIP 归它：

> **`费用与资格` 收两类：申请季要付的钱（申请费及其减免），与项目自身的资格属性（CIP 分类、STEM 指定）。二者都由选校消费，owner 不变。**

⚠️ **粒度是项目级，不是渠道级。** #34 已查实 CIP 与 `program_key` 两头对不上（Cornell 一个 graduate field 下 MEng/MS/PhD 共用一码；Columbia SIPA 一个 channel 内四个 MPA 变体四个 CIP），所以它的家是覆盖层 `## 项目级差异` → `### <program_key>` → `#### 费用与资格`，**不是渠道层的 `## 费用与资格`**。三个样例现在都填在渠道层，是**错位**——`##` 底下一条 `待核实` 结构上完全合法，**没有任何检查会报它**，这是一次语义修正，归 [#58](https://github.com/jiangxidong/EduApplication/issues/58)。

⚠️ **在 #58 落盘之前，三个 prototype 分支的样例与本节直接冲突（它们把 STEM 填在渠道层），以本节为准。** 这条冲突**没有任何机械检查会报**（`##` 底下一条 `待核实` 结构合法），所以只能靠这句话拦住下一个照着样例学形态的 session。

**落进去的是 `CIP code`，不是 STEM 结论**——STEM 资格是 CIP 与 DHS 全国名单的函数，而那张名单不属于任何学校、任何申请人，落进工作区就是镜像。见 [ADR 0018](0018-a-global-lookup-table-stays-out-of-the-workspace.md)。

### 检查表：不新增

限定 5 管的是**改契约的人**，不是工作区的内容。它要验的是「这次给词表加项之前，被援引的那些节有没有范围话」——参照物（范围话）与被检对象（加项这个动作）同处一份**可被同一次提交一起改写**的文档，正是 [ADR 0017](0017-a-check-that-compares-against-a-forkable-copy-is-vacuous.md) 判为**恒真**的那个形状：谁要加项，顺手补一句宽到能容下自己那条事实的范围话，检查照样全绿。它靠人读、靠 review，不靠脚本。写明于此，免得下一个 session 以为它被机械保护着（同限定 2 `claims.md` 那条的纪律）。

[#28](https://github.com/jiangxidong/EduApplication/issues/28) 在样例上**实测**本 ADR 的机械判据，两处不成立，**收紧了规则、正文一字未改**：

- **前缀匹配之前多一步剥离。** 上面写的「封闭词表 + 前缀匹配 + 禁止互为前缀」在样例上**六个节 FAIL**——坏的不是后缀，是**前缀**：`## 🔴 推荐信机制 —— 风险 A：冒名发信` 的 `🔴 ` 顶在节名之前，`index() == 3` 不是 `1`。规则改为**先剥掉标题行首所有不是汉字 / 拉丁字母 / 数字的字符，再做前缀匹配**。这不是第二次取舍，是本 ADR 那次取舍再走一步——选前缀匹配而不是「标题逐字相等」的理由正是**容纳人写的东西**，而 `🔴` 前置是全 repo 的书写习惯（`git grep '^#\+ *[🔴⚠️🔒]'` 命中 9 处，`CONTRACT.md` 自己占 3 处）。🔴 它**绑 locale**：`LC_ALL=C` 下静默失效，检查脚本必须显式设 `LC_ALL=en_US.UTF-8`（`CONTRACT.md` §4.5）。
- **孤儿检查六条换了一条，仍是六条。** 删掉第 4 条「**节按词表顺序排列**」——它不定任何 owner，只买 diff 稳定，却要求 owner **插入**而不是追加（后到的 `## 项目内容` 得插进别人的两个节中间，而追加只碰文件尾）。新增一条：**`### <program_key>` 之下的每一行必须落在某个 `#### <法定节名>` 内，裸行非法**。样例覆盖层的 9 行裸行没有违反任何**已写下来的**规则（原第 6 条只约束 `####` 的位置，不要求 `###` 之下必须有 `####`，零个 `####` 时空过），但在**规则层面**它们恰恰是本 ADR 两条禁止里的第二条——**一条事实找不到写入者**（覆盖层不带 owner，owner 由 `####` 递归决定）。
- **检查判结构，不判「谁写的」。** 新增那条是**结构**规则；**谁有权写那个 `####`** 仍归唯一写入者规则，两条不耦合。这是必要的分开：覆盖层里 `Academic Statement 字数` 归 `#### 文书规格`（owner = 文书），而它是**选校**期发现的——「发现缺口的人」与「有权记下缺口的人」本就不是同一个。真实运行时认下这一点（选校发现了也不落盘，缺席即「没查」）；`sample-workspace/` 是 [ADR 0010](0010-personas-ignite-assertions-they-are-not-examples.md) 的点火器、人手搭的夹具，**只需过结构那一关**。
