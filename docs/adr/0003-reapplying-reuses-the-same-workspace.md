# 二申在同一个工作区换季，不新开工作区

一个人今年被拒、明年再申，可以新开一个工作区（干净、隔离、上一季的错误状态不会渗进来），也可以在原工作区把 `season` 改到下一季。

决定：**同一个工作区改 `season`**。二申用户最值钱的资产——申请人画像、素材库、旧文书与其版本历史、推荐人关系——100% 可复用，新开工作区等于把「跨会话续得上」这个核心赌注扔掉一次。

换季**不清空任何内容**，只做两件事：全表证据降级（保留上季链接），以及 `status` 回退。

## Consequences

`dropped` 是回退的**唯一例外**。判别式不是「所有状态都过期」，而是「这个状态断言的是本季动作，还是一个持续判断」：`shortlist` / `applying` / `submitted` 都在断言本季动作，跨季即失真；`dropped`（「这个项目不适合我」）是持续判断，不随季节失效，全部回退会逼用户把去年排掉的项目再排一遍。

代价：排除理由本身可能过期（当年因为没考 GRE 排掉，今年考了）。因此换季时 `dropped` 的理由进自查清单提示复核，但**不自动改状态**——自动改会让用户失去对排除决定的控制权。

`log.md` 会跨季堆积，这可接受：它 append-only 且每段带日期，记的是历史观察值，不是会失真的镜像。
