01 · ARTIFACT CHAIN

八个阶段，八件工件：从一张地图票走到一份可交接的规格

决策不是终点，工件才是——每个阶段交出什么，决定下一个阶段能不能开工。P4 是整条链唯一的转轴：它左边的输入是检查脚本，右边的输出是七张可执行的票。

它怎样帮助目标：把 #82 之前的一切读成「为一份规格攒够可交接的工件」。四条 research/* 取证分支在 P0–P1 汇进词汇表与 ADR，两条 prototype 分支里只有 state-layer 对 CI 还有活依赖——它持有 CONTRACT.md，而 main 上那个目录是空壳，所以两个 CI job 每次都得先把分支借过来（图上那条虚线）。代价是一批指向它的死链已经随 plugin 分发出去了（#64 未解决）。另有一条与并行无关的独立纪律：关票 ≠ 落盘 ≠ 提交，已发生三次（#16→#21、#9→#13→#23、#22→#24）。还有一件必须说明的事：地图票 #3 至今 OPEN，而且是按设计留开的——它的终点定义是「决策锁定」不是「代码发布」；但它的正文已经陈旧（声称 #66–#81 里还有 15 张开着，实际只剩 #66）。这恰好是 #82 对自己的预言：凡复述处都会陈旧。

02 · SESSION TOPOLOGY

并行扇出、单点冻结、串行收束——以及并行的四张账单

91 张票落在约 51 小时内、08-15T23 一小时关掉 14 张；而实现轨是一条相邻约 30 分钟的严格串行链。两种拓扑之间只隔一个 #82。

它怎样帮助目标：并行不是效率修辞，它有可核实的账单。形态 ③ 的后果之一：#26 先 git add CONTEXT.md 提交为 fbc2d00，把 #15 的九处改动一并卷走，commit message 一个字没提 #15——丢的不是内容，是可追溯性。后果之二：三个并行 session 各自 ls docs/adr/ 拿下一号，结果两个 0011；规程是「后落的让号」，但在 #38 现场双向礼让把它退化成活锁（两个 session 同建 0014、同时让到 0015、再撞一次，因为双方都判自己是后落的）。止损靠的是公开声明：号归引用更多的一方、选定后立刻提交钉死、在票和提交信息里明说「我让号，取 NNNN」。而这套规程本身也被诚实降级为「用过一次、无二次样本」——#66 因此故意留开，ADR 0017 自己的作废条件要求更多样本，现在判就是无据裁决。

跨图交接：这四种形态在产品侧的同构问题——多个写入者共用一份状态——是怎么被结构性堵掉的，见 §03。并行期那 78 张票的相互派生关系，见 票面地图 Map #3。

03 · WRITE OWNERSHIP

唯一写入者绑定的是节，不是文件

四份 SKILL.md 的 Not for: 只解决触发面消歧，那是一张 12 条边的完全图、信息量趋零。真正让四个 skill 共存的是 ADR 0008。

它怎样帮助目标：一个文件有几个写入者不需要辩护；需要辩护的只有两件事，且都禁止：一个结构单元有两个写入者、一条事实找不到写入者。归属判据是消费方——哪个阶段的决策依赖这条事实、哪个阶段取证并落盘；多消费方归最早的那个，而消费不产生写入权（programs.md 那条虚线行就是这个反例位）。移交合法，但要同时满足两个条件：任一时刻仍然唯一 + 不可回流——claims.md 的行所有权就是唯一一条这样的边，所以它拿走了这张图的橙色。另外两件必须点名的事：documents/ 七槽位里 identity 是禁读区，只做存在性与规格检查、不读内容（判据是「读了也没用」不是「敏感」）；以及图上画的是 skill，绑定的其实是阶段——将来重拆 skill，这张归属表一行都不用动。

跨图交接：这条决定的取证过程（#9 / #4 / #18 / #12 / #23 / #25 / #28 的连锁）见 票面地图 Map #3 的契约与真相源两节；这四个 skill 各自是哪张票交付的，见 §01 的 P5–P6。
