>
> **分支假设**：`/prototype` 的两条路（LOGIC / UI）都不严格适用。本票问的是「表格怎么排版、措辞怎么写、判断放哪」——更接近 **UI 分支**，所以做法是：**同一份数据的 3 个变体，用标题切换而不是 URL 参数**。
>
> **样例数据纪律**：本原型讨论的正是「证据纪律」，所以**没有一个 `✓` 是编的**。带 `✓` 的事实全部来自 2026-08-15 抓取的 Columbia DSI 招生页；其余一律 `待核实`。表格看起来很空——**这就是真实稀疏度下的样子**，也正好把「待核实自查清单」压满。

## 0. 三个变体在争什么

本票的 6 个子问题里，有 3 个其实是**同一个问题**：

- 已锁定的证据标记是 **二元**（`✓ <官网链接>` / `待核实`），它是为**事实**设计的：deadline、学费、门槛。
- 「假保底」（方向极挤）是**判断**，永远不会有官网链接。euro-grad-apply 的零出处不是懒，是结构性的。
- 「分档」（冲刺/匹配/较稳）同样是判断——票 #5 已经给出收据：**五所样本无一公开院校分级名单**，卡本科院校层级也不公开。所以分档单元格**永远拿不到 `✓`**。

加第三种标记会破坏已锁定的二元决策。所以三个变体真正要你选的是：

> **判断放在哪，读者才不会把它当成有出处的事实？**

- **变体 A**：判断留在表内，但物理分区（事实区 ‖ 判断区）
- **变体 B**：判断降级出表，表格纯事实，判断另起一节并强制写「依据 + 可被推翻的条件」
- **变体 C**：一个项目两行——事实行 + 口径行，口径行同时承载分档理由与录取率口径

三个变体共用同一批样例数据与同一份自查清单（第 4 节），只是判断的落点不同。

## 3. 三个变体不争的部分（已锁定，不重开）

| 项 | 已锁定 |
|---|---|
| 证据标记 | **二元**：`✓ <官网链接>` / `待核实`。**只占表格一列**，不做 TTL，标记不进散文 |
| 换季 | 状态文件头记 `申请季`；换季后全表 `✓` 自动降级 |
| 自查清单 | 所有 `待核实` 自动汇成用户自查清单（第 4 节） |
| 行粒度 | **一行 = 一个项目**（学校 · 学院 · 项目名）。校级门槛是谎，因为最小分叉粒度是学院（#5） |
| 录取概率 | **不给**。区别见下 |

**录取率 vs 录取概率——这条必须在页面上看得见：**

- ✅ **学校公布的录取率**：是事实，有链接就能标 `✓`，但**必须带口径**（哪一年、全体还是国际生、是否含 waitlist）。查不到口径时写「<数字>（口径未公开：年份/群体不明）」，不要裸给数字。
- ❌ **给你的录取概率**：不做，任何变体都不做。「你有 35% 概率被录」不出现在任何一列。

## 5. 从清单收敛到最终投递名单

清单是「候选池」，投递名单是「决定」。原型里用一列表达：

| 项目 | … | 决定 |
|---|---|---|
| Columbia · DSI · MSDS | … | **投**（2026-08-15 定） |
| Columbia · SEAS · MS CS | … | 待定 |
| UT Dallas · ECS · MSCS | … | 不投（理由：<一行>） |

**规则草案**：

1. `决定` 只有三个值：`投` / `待定` / `不投`。`不投` 必须带一行理由（否则半年后自己会忘记为什么排除）。
2. **定稿闸门**：任何标 `投` 的项目，其 `申请截止` 不允许停留在 `待核实`——截止日不确定就不能进投递名单。
3. 「投」的集合就是网申准备包（票 #8）的输入。

> **与票 #4 的交接（本票不定）**：这张表存成什么文件、放哪个目录、叫什么名字、`申请季` 字段的确切写法——全部归 [#4 状态层的文件契约](https://github.com/jiangxidong/EduApplication/issues/4)。本票只定**表的形状**：列、判断落点、措辞、决定列语义。

## 6. 需要你拍板的（这是 HITL 票，我不替你答）

1. **变体选 A / B / C 哪个？** 或者哪个的哪一半。
2. **分档中文措辞**：`冲刺 / 匹配 / 较稳` ？还是 `冲刺 / 匹配 / 相对稳妥`？（已锁定 **不用「保底」「稳了」**——safer 不是 safe）
3. **分档档位不足时**：只有 5 个候选且全是冲刺，要不要强行凑出「较稳」档？（我倾向：不凑，直接说「你目前的池子里没有较稳档」）
4. **伪保底**：接受「必须写满 依据 + 作废条件，否则不写」这条硬规则吗？代价是很多真实的直觉会因为写不出依据而被丢掉。
5. **录取率列**：进表（作为事实列，带口径）还是不进表？现实是绝大多数美国 coursework master 根本不公布项目级录取率。
6. **表宽**：终端里 7 列会换行成一坨。要不要牺牲一列（比如学费移到口径/脚注）？
